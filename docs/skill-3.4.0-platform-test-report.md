## 4. 测试驱动优化记录

### 4.1 时间预算与疲劳降载

- 固化 10h 校准等式：`4 + 2.5 + 2 + 0 + 1.5 = 10h`。
- 缓冲保持未分配，不从缓冲安排复盘或可选任务。
- 疲劳校准改为一张总时长 4h 的唯一核心任务卡：0.5h 清点阻塞 + 3.5h 最小行动。
- 明确 `0.5 + 3.5 = 4h` 和 `0.5 + 3.5 + 1 + 3 = 8h`，停止追赶旧欠账。

### 4.2 事实门禁

- 用户已经说明没有可靠样本时，不搜索、不估算、不复述模型记忆中的区间。
- 最终答案不得出现具体薪资区间、涨跌数字或“量级合理”等变相猜测。
- 输出改为“尚未验证 + 缺失证据 + 最短取证步骤”。

### 4.3 学习评估

- 复测题只给题目、作答要求和不含答案的评价维度。
- 新增硬门禁：用户作答前禁止出现“预期答案/预期产出/参考答案/评分关键词”、正确选项、数值结果或完整解法。
- 该规则来自一次在线失败样例：模型曾把答案放在“预期产出”中；修复后复测通过。

### 4.4 记忆与隐私

- 敏感信息请求强制进入 MEMORY 路由。
- 明确拒绝保存密码、令牌、身份证号、银行卡、精确住址等敏感值。
- 不复述用户尚未提供或已经提供的敏感内容，只给安全替代方案。

## 5. 平台运行时发现

以下问题属于易思捷宿主层，不是 Skill 包内部逻辑：

1. 管理端曾显示 `ready`，但个别线程先尝试 `/mnt/skills/custom/...` 并返回 404。使用平台原生 `$compass-student-growth` 标记、显式绑定 Skill，并验证 `user` 路径真实读取，可显著提高稳定性；最终通过线程均成功读取 `user` 路径。
2. 高频连续测试曾出现 `Could not start sandbox container: all candidate ports are already allocated by Docker`。改为逐项、低频测试后恢复。
3. `qwen3-32b` 与 `qwen3-vl-32b-instruct` 的 Skill 调用稳定性低于 `qwen3.6-35b-a3b`，因此正式验收选择后者。
4. 当前模型响应会在 `</think>` 前包含内部推理文本。测试器只验收标签后的正式答案并保留告警；平台应在渲染层隐藏内部推理，Skill 自身无法保证宿主不发送该段。

这些告警没有被降级为“通过条件”。正向用例只有在成功读取最新版 `user` 类别 `SKILL.md` 且业务断言全部满足时才通过。

## 7. 正式使用建议

1. 在易思捷对话中选择“指南针·大学生成长导师”。
2. 使用平台插入的 `$compass-student-growth` 标记发起首轮请求。
3. 优先选择 `qwen3.6-35b-a3b`。
4. 若线程提示 Skill 文件 404，重新新建对话并再次从技能选择器插入，而不是接受未加载 Skill 的降级回答。
5. 平台维护方应清理已失效的 `custom` 路径索引、增加沙箱端口回收，并在界面层隐藏 `</think>` 前内容。
