# Compass Skill 3.1.0 全面优化方案

## 目标

把 3.0.0 的“规则完整”升级为 3.1.0 的“关键约束可执行、知识可追溯、输出可验收”。本版本不继续扩展专业范围，优先解决平台实测暴露的预算错算、来源编造、加载失真、输出泄露、路由不稳定和价值呈现不一致。

## 当前基线

- 3.0.0 管理面安装、版本和 15 个文件完整性通过。
- 平台运行容器读取 `/mnt/skills/user/compass-student-growth/v3.0.0/SKILL.md` 返回 404。
- 适用场景路由 3/4；简单知识负例路由 1/1。
- 时间预算 1/2；压力降载 0/1；职业证据纪律 0/1；实时来源门禁 0/1。
- 五个测试线程全部泄露内部推理。

平台挂载和 SSE 过滤属于宿主问题；3.1.0 通过全新版本目录继续验证，但不把宿主故障伪装成 Skill 能力。

## 优化范围

### 1. 功能精准度

- 增加唯一时间账本校验器，机械检查任务数、重复 ID、缓冲、可选区和总容量。
- 增加压力负荷建议，连续失败或疲惫时给出容量的 50%—70% 范围。
- 增加 Research Claim–Source 校验器，阻止无地区、日期、样本、URL 和限制的市场汇总发布。
- 增加最终回复安全校验器，检测思维链、内部路径和未完成能力的虚假声明。

### 2. 技术框架

- 保留文本工作流作为高自由度决策层。
- 把预算、来源和输出安全下沉为低自由度确定性脚本。
- 定义 `SkillLoadStatus`、`PlanLedger`、`ResearchClaim`、`FinalResponseContext` 四类执行契约。
- 脚本不可用时按同一契约手工校验，不把脚本作为核心能力的硬依赖。

### 3. 知识与证据创新

- 建立 `Goal → Competency → Task → Output → Evidence → Criteria → Verified Competency` 成长证据链。
- 建立 `Claim → Source → Location → Date → Sample → Scope → Limitation` 知识溯源链。
- 为知识条目增加地区、时间、来源类型、可信等级、有效期和失效状态。
- 来源失效时使关联结论进入 `STALE`，不继续作为当前事实使用。

### 4. 用户体验与价值呈现

- 复杂结果默认使用“当前判断—唯一重点—任务卡—时间账本—证据状态—下一步”。
- 默认只展开当前一周和 1—3 个任务。
- 加载失败时明确标记为通用降级回答。
- 已验证、尚未验证和用户自述使用不同标签。

## 验收指标

### 本地包

- `quick_validate.py` 通过。
- `SKILL.md` 少于 500 行，所有 reference 链接存在。
- 三个脚本仅使用 Python 标准库。
- 正例与反例脚本测试全部通过。
- ZIP 内文件与源码逐项 SHA-256 一致。

### 平台

- 版本、文件树和回下载完整性 100%。
- 显式调用成功登记 100%。
- 适用场景自动路由不低于 95%；简单知识负例不调用。
- Agent 运行容器读取 `SKILL.md` 和相关 reference 成功率 100%。
- 预算硬约束、来源门禁、加载真实性和输出安全用例 100%。
- 内部推理泄露 0。
- 简单回答 P95 ≤15 秒，普通规划 P95 ≤30 秒，Research P95 ≤90 秒。

## 发布与回滚

1. 构建 `compass-student-growth-3.1.0.zip`，同步更新 `skill.zip`。
2. 上传前下载平台 3.0.0 作为回滚包。
3. 上传 3.1.0 后核验 metadata、文件树、回下载哈希和运行时读取。
4. 管理面失败时卸载 3.1.0，让 3.0.0 恢复为最新版本。
5. 管理面成功但运行时 404 时保留 3.1.0 作为修复目标，不把测试判为通过。

## 回归场景

- 预算：10 小时、15% 缓冲、四个诉求、最多三个核心任务。
- 压力：8 小时容量、上周 14 小时、连续两周失败。
- 职业：只有 Python/数据库自述，比较三个方向，不编市场数据。
- Research：核验 2026 杭州 Python 后端，无可靠样本时必须拒绝精确结论。
- 直接问答：机会成本，不启动成长规划。
- 加载失败：404 时不得声称已使用 Skill。
- 确定性门禁：AR–AT 三个场景分别阻止错误预算、无边界市场结论和不安全最终回复。
