# Compass Skill 3.2.0 平台测试报告

测试日期：2026-08-11
测试平台：易思捷超级智能体平台
测试版本：`compass-student-growth` 3.2.0

## 1. 总体结论

3.2.0 已成功发布为平台当前正式版本。管理面显示 `active / enabled / ready`，平台回下载包包含全部 23 个文件；除平台向 `manifest.yaml` 追加作者字段外，其余 22 个业务文件与本地发布包逐字节一致。

但 Agent 运行容器读取 `/mnt/skills/user/compass-student-growth/v3.2.0/SKILL.md` 返回 404，用户 Skill 目录为空。因此本轮结论必须分层：

- 本地制品与培训规范对齐：通过。
- 平台上传、解析、本地化状态与回下载：通过。
- 显式 Skill 路由登记：通过。
- 自动压力场景调用：失败，模型识别到适用但未实际调用。
- Skill 运行时加载：失败，被平台挂载链路阻断。
- 3.2.0 工作流、示例、校验器的平台实际效果：不能判为通过。
- 简单知识负例不触发 Compass：通过。
- 最终响应思维链隔离：失败。

3.2.0 是可发布、可回滚、可复现测试的完整制品，但当前不能宣称其核心能力已经在平台运行态生效。

## 2. 基于培训内容完成的优化

### 2.1 分层与边界

- 保持 L1 manifest、L2 `SKILL.md`、L3 scripts/references 的渐进式结构。
- `SKILL.md` 新增显式输入、输出、不应使用场景和异常处理。
- 负例覆盖简单常识、无关代码修复、未经授权外部操作和加载失败后的虚假能力声明。
- 主指令保持 209 行，低于培训建议的 500 行上限；18 个内部链接全部存在。

### 2.2 示例与价值呈现

- 新增 4 个具体输入/输出示例：正常预算、压力降载、证据不足、简单知识负例。
- 复杂任务继续使用一屏式价值卡，突出当前判断、唯一重点、任务卡、时间账本、证据状态和下一步。
- 保留预算守恒、事实门禁、压力降载、输出安全和加载真实五个发布级硬门禁。

### 2.3 测试金字塔

- 单元层：pytest 覆盖预算、重复任务、超载、可选区、非法日期、研究边界和响应安全。
- 集成层：`tests/integration_cases.json` 包含 8 个可复现语义用例。
- 平台 E2E 层：显式调用、自动压力和负向路由各保留独立线程与原始 SSE/状态证据。
- CLI 契约验证 stdout 只输出单一 JSON，stderr 不混入调试内容。

## 7. 下一步优化方案

### P0：修复平台发布到运行的挂载链路

1. `localization_status=ready` 前必须在 Agent 容器验证 `SKILL.md` 存在、可读、非空。
2. 本地化任务记录源目录、运行目录、版本、文件数、总字节数和清单哈希；任一不一致标记 `failed`。
3. 管理存储到 `/mnt/skills/user/<name>/v<version>` 使用原子复制或只读挂载，切换成功后再更新当前版本。
4. 为已经处于 `ready` 但运行目录为空的版本提供“重新本地化/重挂载”，避免通过重复上传修复。
5. P0 验收：显式和自动路由各 10 次，20/20 读取 3.2.0 `SKILL.md`；至少一个 reference 和一个 script 的读取成功率 100%。

### P0：修复平台输出安全

1. 在 SSE 和最终消息两个出口统一剥离思维链、系统路径、工具草稿和 think 标签。
2. 即使 Skill 加载失败，平台级过滤仍必须生效，不能依赖 Skill 自己约束模型。
3. P0 验收：正向、压力、负向各 10 次，用户可见消息和可持久化消息中的内部过程泄露均为 0。

### P1：增强自动调用和可观察性

1. 将运行状态拆成 `ROUTED → INVOKED → LOADED → VALIDATED → RESPONDED`，每段记录版本、耗时和错误码。
2. 路由评测单独统计“模型认为适用但未调用”，避免把语义识别误报为调用成功。
3. 将预算/压力触发词纳入平台路由回归：真实容量、超载、连续失败、疲惫、缓冲、时间账本。
4. P1 验收：8 个集成用例各重复 5 次；正例调用率不低于 95%，负例误触发率不高于 5%。

### P1：接入确定性校验器

1. 计划回复前调用 `validate_plan.py`；不通过时禁止发送未经修正的时间账本。
2. 实时研究回复前调用 `validate_research.py`；缺来源边界时只能输出“尚未验证”。
3. 最终回复前调用 `validate_response.py`，并保留宿主级二次过滤。
4. P1 验收：预算、压力、研究和输出安全用例全部命中相应校验器，并保存机器可读结果。

### P2：形成比赛展示闭环

1. 运行 8 个集成用例与 46 个扩展验收场景，保存输入、调用、读取、校验、输出、耗时和评分。
2. 选取“无 Skill 基线 / 3.2.0 有 Skill”的同题对照，展示时间守恒、澄清问题数、来源完整率和任务可验收度差异。
3. 形成 3 分钟演示路径：真实问题 → 自动触发 → 加载证据 → 校验器通过 → 一屏价值卡 → 结果复盘。
4. 知识库展示 Claim–Source 的 DRAFT、ACTIVE、STALE、RETIRED 生命周期，以及学习 Evidence 到 Verified Competency 的升级条件。

## 8. 复测通过标准

- 管理面、运行面和行为面必须同时通过。
- 3.2.0 绑定后读取路径必须为 3.2.0，文件非空且哈希与发布清单一致。
- 10 小时预算保留 1.5 小时缓冲，核心与支持任务合计不超过 8.5 小时，可选区为 0。
- 8 小时连续失败压力场景降到约 4–5.5 小时，通常仅一个核心任务。
- 缺可靠样本时不发布薪资、比例、趋势或岗位需求量。
- 简单知识负例不调用 Compass，不扩展成长规划，严格遵循用户长度要求。
- 所有最终与持久化回复不含思维链、内部路径、工具草稿或虚假能力声明。
