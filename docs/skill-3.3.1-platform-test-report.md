## 7. 尚存问题与优化优先级

### P0：平台统一清理内部推理

现象：四类测试均可能在答案前输出英文内部分析和 `</think>`。即使 `thinking_enabled=false` 且 Skill 明确要求“不输出内部推理”，问题仍存在。

建议平台侧：

1. 在 SSE 事件转用户消息前识别 `think` 段；
2. 删除 `</think>` 及其前面的内部推理，只保留最终答案；
3. 同时处理完整标签、只有闭合标签、分片跨事件三种情况；
4. 对“未调用任何 Skill”的普通问答加入回归测试；
5. 保留原始调试事件在受控日志中，不发送到用户可见消息。

### P1：把确定性校验接入平台运行链

目前 ZIP 内有 `validate_plan.py`、`validate_research.py` 和 `validate_response.py`，但平台模型不一定实际执行脚本。建议为 Skill 提供明确、可调用的本地脚本工具，使预算、任务数量、来源字段在回复前由确定性程序校验，而不是只依赖模型遵守文本规则。

### P1：建立自动化平台回归集

至少固定以下断言：

- 预算明细逐项求和等于总计；
- 正时长任务和任务卡均不超过 3；
- 可选区默认为 0h；
- 疲劳场景核心负荷落在合理降载区间；
- 证据不足时出现“尚未验证”且没有伪造精确数字；
- 负例不调用 Skill；
- 用户可见答案中不存在 `think` 标签和内部推理。

### P2：研究建议的来源安全

在事实门禁测试中，Skill 正确拒绝编造薪资，但仍可能给出未经实际访问验证的站点路径。后续可进一步要求：不能确认可访问性的 URL 只给站点名称和搜索步骤，不拼接深层链接。
