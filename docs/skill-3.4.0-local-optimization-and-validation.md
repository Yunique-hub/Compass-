## 4. 3.4.0 核心优化

### 4.1 入口与路由精简

- 将主流程统一为 `ROUTE → READ → EXECUTE → VERIFY → RESPOND`。
- 收敛为 PLAN、LEARN、RESEARCH、MEMORY、IMPROVE、DIRECT 六类路由。
- 明确输入、输出、拒绝边界、失败降级和资源读取顺序。
- 删除版本绑定表述，使后续小版本更新不需要反复改写运行规则。

### 4.2 规划准确性

- 规划只允许 1–3 个核心目标，最多 3 个正工时任务或卡片。
- 第 4 个及以后目标只能作为可选项或停止项，工时必须为 0。
- 时间预算必须显式验算；10 小时示例统一为 `4 + 2.5 + 2 + 0 + 1.5 = 10h`。
- 高压或疲劳状态默认把承诺量降至可用时间的 50%–70%，通常只保留一个核心目标。
- `validate_plan.py` 现在会把可选任务工时计入总量，避免隐藏超预算。

### 4.3 学习与评估

- 保留“诊断—教学—练习—评分—补救—复测”的闭环。
- 将可验证结果与泛化建议分开，避免把未经测试的判断写成结论。
- 增加盲复测硬门禁，禁止用“预期产出”、验收标准或评分关键词变相泄露答案。
- 压缩重复说明，使用户更快获得可执行步骤。

### 4.4 职业研究与证据安全

- 薪资、岗位、政策、截止日期等外部事实必须标注来源、地区、时间和验证状态。
- 禁止猜测深层链接；找不到可靠来源时明确标记“尚未验证”。
- 增加来源生命周期 `DRAFT → ACTIVE → STALE → RETIRED`。
- `validate_research.py` 新增日期区间反向和重复 URL 检测。

### 4.5 记忆、隐私与安全

- 将记忆边界、最小文件集合、恢复/提交规则、经验可信度和隐私要求合并为一个参考文件。
- 默认只保存长期有用且经用户确认的信息；敏感信息不写入持久记忆。
- 不替用户作高影响决定，不执行未经授权的外部操作。
- `validate_response.py` 扩充中英文内部推理泄露检测。

### 4.6 构建与发布结构

- 新增标准库构建脚本 `scripts/build_release.py`，使用明确的运行文件白名单。
- 发布包不包含 `docs/`、`tests/`、`README.md`、构建脚本、包校验器和缓存。
- `scripts/validate_platform_package.py` 同时验证入口、版本、作用域、界面元数据、单顶层目录和开发文件泄漏。
- 同一次构建生成正式版本包和平台兼容文件 `skill.zip`。
